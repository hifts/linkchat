# 心跳包和断线重连机制工作流程文档

## 1. 概述

本文档详细描述了客户端与服务器之间的心跳包机制和断线重连机制的工作流程。这两个机制协同工作，确保客户端与服务器之间的连接稳定性和可靠性。

### 1.1 核心组件

- **HeartbeatManager（心跳管理器）**：负责定时发送心跳包、监控心跳响应、检测连接超时
- **ReconnectManager（重连管理器）**：负责检测网络断线、自动重连、保存登录状态
- **NetworkManager（网络管理器）**：负责底层网络通信、数据包收发

---

## 2. 心跳包机制

### 2.1 心跳机制设计目标

1. **保持连接活跃**：定期向服务器发送心跳包，防止连接因长时间无数据传输而被中间网络设备断开
2. **及时检测断线**：通过监控心跳响应，快速发现网络连接异常
3. **触发重连机制**：当检测到连接超时时，通知重连管理器启动重连流程

### 2.2 心跳参数配置

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 心跳间隔（m_heartbeatInterval） | 5000ms (5秒) | 每隔多久发送一次心跳包 |
| 心跳超时（m_heartbeatTimeout） | 15000ms (15秒) | 超时检查的时间间隔 |
| 最大错过次数（m_maxMissedHeartbeats） | 3次 | 连续错过多少次心跳响应后判定为超时 |

### 2.3 心跳工作流程

```
┌─────────────────────────────────────────────────────────────┐
│                      心跳机制工作流程                          │
└─────────────────────────────────────────────────────────────┘

    启动心跳
       ↓
   [初始化状态]
   - m_isActive = true
   - m_missedHeartbeats = 0
       ↓
   ┌──────────────────────────────────────┐
   │  启动两个定时器                        │
   │  1. 心跳发送定时器 (5秒)               │
   │  2. 超时检查定时器 (15秒)              │
   └──────────────────────────────────────┘
       ↓
   ┌──────────────────────────────────────┐
   │  定时器触发：发送心跳                  │
   │  - m_missedHeartbeats++               │
   │  - emit needSendHeartbeat()           │
   └──────────────────────────────────────┘
       ↓
   ┌──────────────────────────────────────┐
   │  NetworkManager 发送心跳包到服务器     │
   └──────────────────────────────────────┘
       ↓
       ├─────────────┬─────────────┐
       ↓             ↓             ↓
   收到响应      超时检查      继续等待
       ↓             ↓
   [重置计数]    [检查次数]
   - m_missedHeartbeats = 0
   - 重启超时定时器
       ↓             ↓
   继续循环      ┌──────────────────────┐
                 │ 错过次数 >= 3 ?       │
                 └──────────────────────┘
                     ↓           ↓
                   是           否
                     ↓           ↓
              [触发超时]    继续监控
              emit heartbeatTimeout()
                     ↓
              通知重连管理器
```

### 2.5 心跳超时判定逻辑

心跳超时的判定采用**累计错过次数**的方式：

1. 每次发送心跳包时，`m_missedHeartbeats` 计数器加1
2. 如果收到服务器的心跳响应，计数器重置为0
3. 超时检查定时器（15秒）定期检查计数器
4. 当 `m_missedHeartbeats >= 3` 时，判定为连接超时

**示例时间线：**
```
时间 0s:  发送心跳 #1, missedHeartbeats = 1
时间 5s:  发送心跳 #2, missedHeartbeats = 2
时间 10s: 发送心跳 #3, missedHeartbeats = 3
时间 15s: 超时检查触发，missedHeartbeats >= 3，判定超时
```

## 3. 断线重连机制

### 3.1 重连机制设计目标

1. **自动恢复连接**：网络断开后自动尝试重新连接服务器
2. **智能重连策略**：采用指数退避算法，避免频繁重连造成服务器压力
3. **保持用户状态**：保存登录信息，重连成功后自动登录
4. **状态管理**：维护连接状态，协调各组件行为

### 3.2 连接状态定义

```cpp
enum ConnectionState {
    Disconnected,   // 已断开 - 初始状态或连接断开
    Connecting,     // 连接中 - 正在建立TCP连接
    Connected,      // 已连接 - TCP连接已建立且登录成功
    Reconnecting    // 重连中 - 正在尝试重新连接
};
```

### 3.3 重连参数配置

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 初始延迟（m_initialDelay） | 5000ms (5秒) | 第一次重连的延迟时间 |
| 最大延迟（m_maxDelay） | 30000ms (30秒) | 重连延迟的上限 |
| 最大重连次数（m_maxAttempts） | 0 (无限) | 最多尝试重连的次数，0表示无限重连 |
| 自动重连开关（m_autoReconnect） | true | 是否启用自动重连 |

### 3.5 指数退避算法

重连延迟采用指数退避算法，避免频繁重连：

```
第1次重连: delay = 5秒
第2次重连: delay = 10秒 (5 * 2^1)
第3次重连: delay = 20秒 (5 * 2^2)
第4次重连: delay = 30秒 (达到上限)
第5次及以后: delay = 30秒 (保持上限)
```

**算法公式：**
```
delay = min(initialDelay * 2^(reconnectAttempts), maxDelay)
```

## 5. 关键场景分析

### 5.1 场景1：网络短暂抖动

**情况描述：** 网络出现短暂波动，1-2个心跳包丢失，但随后恢复正常

**处理流程：**
1. 心跳包发送，但未收到响应，`missedHeartbeats` 增加到1
2. 5秒后再次发送心跳包，仍未收到响应，`missedHeartbeats` 增加到2
3. 网络恢复，第3次心跳包收到响应
4. 调用 `onHeartbeatReceived()`，重置 `missedHeartbeats = 0`
5. 连接继续正常工作，**不触发重连**

**优点：** 避免因短暂网络波动而频繁重连

### 5.2 场景2：网络完全断开

**情况描述：** 网络线缆拔出或WiFi断开，连接完全中断

**处理流程：**
1. 连续3次心跳包未收到响应（15秒内）
2. `onCheckTimeout()` 检测到 `missedHeartbeats >= 3`
3. 发射 `heartbeatTimeout()` 信号
4. ReconnectManager 收到信号，设置状态为 `Disconnected`
5. 启动重连流程，第1次延迟5秒
6. 5秒后尝试连接，失败
7. 第2次延迟10秒，再次尝试
8. 持续重连直到网络恢复

### 5.3 场景3：服务器重启

**情况描述：** 服务器进行维护重启，客户端需要重新连接

**处理流程：**
1. 服务器关闭，TCP连接断开
2. NetworkManager 检测到 `disconnected()` 信号
3. 通知 ReconnectManager，状态变为 `Disconnected`
4. 心跳管理器停止工作
5. 启动重连流程，使用指数退避算法
6. 服务器重启完成后，某次重连尝试成功
7. 自动使用保存的登录信息重新登录
8. 恢复心跳机制，连接恢复正常

### 5.4 场景4：客户端休眠后唤醒

**情况描述：** 笔记本电脑休眠后唤醒，网络连接可能已失效

**处理流程：**
1. 休眠期间，所有定时器暂停
2. 唤醒后，定时器恢复，但TCP连接可能已断开
3. 心跳包发送失败或超时
4. 触发心跳超时机制
5. 启动重连流程
6. 重新建立连接并自动登录

## 6. 配置建议

### 6.1 心跳参数调优

根据不同的网络环境和应用场景，可以调整心跳参数：

**局域网环境：**
- 心跳间隔：3秒
- 心跳超时：10秒
- 最大错过次数：3次

**移动网络环境：**
- 心跳间隔：10秒（节省流量）
- 心跳超时：30秒
- 最大错过次数：3次

**高可靠性要求：**
- 心跳间隔：2秒
- 心跳超时：8秒
- 最大错过次数：4次

### 6.2 重连参数调优

**快速重连策略（适用于稳定网络）：**
- 初始延迟：2秒
- 最大延迟：15秒
- 最大重连次数：10次

**保守重连策略（适用于不稳定网络）：**
- 初始延迟：10秒
- 最大延迟：60秒
- 最大重连次数：0（无限）

## 7. 错误处理和日志

### 7.1 日志级别

- **INFO**：正常的心跳发送、接收、重连尝试
- **WARN**：心跳超时、重连失败、配置异常
- **ERROR**：严重错误，如服务器地址为空、达到最大重连次数

## 8. 优化建议

### 8.1 当前实现的优点

1. **职责分离**：心跳和重连逻辑分离，易于维护
2. **灵活配置**：支持动态调整各项参数
3. **智能重连**：采用指数退避算法，避免服务器压力
4. **状态保持**：保存登录信息，重连后自动登录

### 8.2 可能的改进方向

1. **自适应心跳间隔**：根据网络质量动态调整心跳频率
2. **重连策略优化**：根据断线原因选择不同的重连策略
3. **网络质量监控**：记录网络质量指标，辅助故障诊断
4. **用户通知**：在重连过程中向用户展示友好的提示信息
5. **断点续传支持**：文件传输过程中断线后，重连后继续传输

## 9. 总结

心跳包和断线重连机制是保证客户端-服务器通信稳定性的关键组件。通过合理的参数配置和智能的重连策略，可以在各种网络环境下提供良好的用户体验。

**核心要点：**
- 心跳机制用于**检测**连接状态
- 重连机制用于**恢复**连接状态
- 两者协同工作，确保通信可靠性
- 采用指数退避算法，平衡响应速度和服务器压力
- 保存登录状态，实现无缝重连
