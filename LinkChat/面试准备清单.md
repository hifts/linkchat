## 🎯 核心技术点（必须掌握）

### 1. 网络编程 ⭐⭐⭐⭐⭐

#### TCP 粘包/半包问题
**必答问题**：
- Q: 什么是粘包和半包？
- A: TCP 是流式协议，没有消息边界。粘包是多个小包合并成一个大包，半包是一个大包被拆分成多个小包。

**解决方案**：
```cpp
// 1. 固定长度协议头
struct PDUHeader {
    uint32_t total_len;  // 关键：包含整个包的长度
    uint32_t msg_type;
    uint32_t dest_id;
    uint32_t src_id;
};

// 2. 接收逻辑
void onReadyRead() {
    while (m_socket->bytesAvailable() >= sizeof(PDUHeader)) {
        PDUHeader header;
        m_socket->peek((char*)&header, sizeof(PDUHeader));
        
        if (m_socket->bytesAvailable() < header.total_len) {
            return; // 数据不完整，等待
        }
        
        QByteArray packet = m_socket->read(header.total_len);
        processPacket(packet);
    }
}
```

**关键点**：
- 先 peek 读取头部，不移动读指针
- 检查缓冲区数据是否足够
- 数据完整后再读取整个包

#### 心跳包机制
**必答问题**：
- Q: 为什么需要心跳包？
- A: 检测连接是否存活，TCP 连接可能"假死"（网络中断但未收到 FIN 包）

**实现要点**：
- 客户端：QTimer 定时发送（5 秒）
- 服务端：QTimer 超时检测（15 秒）
- 每次收到心跳包重置定时器

**代码示例**：
```cpp
// 客户端
m_heartbeatTimer->start(5000);
connect(m_heartbeatTimer, &QTimer::timeout, [=](){
    sendMsg(MSG_HEARTBEAT_REQ, QByteArray());
});

// 服务端
void onHeartbeatReceived() {
    m_timeoutTimer->start(15000); // 重置
}

void onTimeout() {
    LOG_WARN("心跳超时，断开连接");
    m_socket->disconnectFromHost();
}
```

#### 断线重连
**必答问题**：
- Q: 如何实现断线重连？
- A: 监听 disconnected 信号，使用指数退避算法重连

**实现要点**：
- 指数退避：5s → 10s → 20s → 30s（最大）
- 保存登录信息，重连后自动登录
- 恢复未完成的文件传输

**代码示例**：
```cpp
void onDisconnected() {
    if (m_autoReconnect) {
        int delay = qMin(m_currentDelay, m_maxDelay);
        QTimer::singleShot(delay * 1000, this, &ReconnectManager::reconnect);
        m_currentDelay *= 2; // 指数增长
    }
}
```

### 2. Qt 高级特性 ⭐⭐⭐⭐⭐

#### Model/View 架构
**必答问题**：
- Q: 为什么使用 Model/View 架构？
- A: 分离数据和显示，便于维护和扩展。Model 管理数据，View 负责显示，Delegate 负责绘制。

**实现要点**：
```cpp
// Model：继承 QAbstractListModel
class ChatModel : public QAbstractListModel {
    int rowCount(const QModelIndex &parent) const override {
        return m_messages.count();
    }
    
    QVariant data(const QModelIndex &index, int role) const override {
        if (role == Qt::DisplayRole) {
            return QVariant::fromValue(m_messages[index.row()]);
        }
        return QVariant();
    }
};

// Delegate：继承 QStyledItemDelegate
class ChatDelegate : public QStyledItemDelegate {
    void paint(QPainter *painter, const QStyleOptionViewItem &option,
               const QModelIndex &index) const override {
        // 自定义绘制气泡、头像、文字
    }
    
    QSize sizeHint(const QStyleOptionViewItem &option,
                   const QModelIndex &index) const override {
        // 计算每条消息的高度
    }
};
```

**关键点**：
- rowCount：返回数据行数
- data：返回指定行的数据
- paint：自定义绘制
- sizeHint：计算每项的大小

#### 多线程编程
**必答问题**：
- Q: 为什么文件传输要用多线程？
- A: 文件读取和发送是 I/O 密集型操作，会阻塞主线程，导致 UI 卡顿。

**实现要点**：
```cpp
class FileTransferThread : public QThread {
    void run() override {
        QFile file(m_filePath);
        file.open(QIODevice::ReadOnly);
        
        while (!file.atEnd()) {
            QByteArray chunk = file.read(64 * 1024); // 64KB
            emit sendChunk(chunk);
            emit progressUpdated(percent);
        }
        
        emit transferCompleted();
    }
};

// 主线程
connect(thread, &FileTransferThread::progressUpdated, 
        progressBar, &QProgressBar::setValue);
```

**关键点**：
- 继承 QThread，重写 run()
- 使用信号槽跨线程通信
- 不要在子线程直接操作 UI

#### 信号槽机制
**必答问题**：
- Q: 信号槽的优势是什么？
- A: 松耦合、类型安全、支持跨线程通信

**使用场景**：
- 网络事件通知（readyRead、disconnected）
- 跨线程通信（子线程 → 主线程）
- UI 事件处理（clicked、textChanged）

### 3. 文件传输 ⭐⭐⭐⭐

#### 分片传输
**必答问题**：
- Q: 为什么要分片传输？
- A: 避免一次性读取大文件占用大量内存，支持断点续传，可以显示进度。

**实现要点**：
- 分片大小：64KB（可配置）
- 分片索引：从 0 开始
- 协议设计：
```cpp
struct FileChunk {
    char fileId[64];
    quint32 chunkIndex;
    quint32 chunkSize;
    // 后面跟实际数据
};
```

#### 断点续传
**必答问题**：
- Q: 断点续传如何实现？
- A: 使用位图记录已接收分片，传输状态持久化，重连后只发送未接收的分片。

**核心数据结构**：
```cpp
struct TransferState {
    QString fileId;
    QString fileName;
    qint64 fileSize;
    int totalChunks;
    QBitArray receivedChunks; // 位图
    QString savePath;
};
```

**恢复流程**：
1. 客户端发送 MSG_FILE_RESUME_REQ
2. 服务端返回 MSG_FILE_RESUME_RESP（包含位图）
3. 客户端检查位图，只发送未接收的分片

**位图操作**：
```cpp
// 设置第 n 个分片已接收
receivedChunks.setBit(n, true);

// 检查第 n 个分片是否已接收
bool received = receivedChunks.testBit(n);

// 计算已接收分片数
int count = receivedChunks.count(true);
```

### 5. 设计模式 ⭐⭐⭐

#### 单例模式
**使用场景**：
- NetworkManager：全局唯一的网络管理器
- FileTransferManager：全局唯一的文件传输管理器
- ConfigManager：全局唯一的配置管理器

**实现方式**：
```cpp
class NetworkManager {
public:
    static NetworkManager& instance() {
        static NetworkManager instance;
        return instance;
    }
    
private:
    NetworkManager() = default;
    NetworkManager(const NetworkManager&) = delete;
    NetworkManager& operator=(const NetworkManager&) = delete;
};
```

**关键点**：
- 静态局部变量（C++11 保证线程安全）
- 禁用拷贝构造和赋值操作

#### 观察者模式
**使用场景**：
- Qt 信号槽机制就是观察者模式
- 网络事件通知、UI 更新

### 技术深度问题

#### Q4: TCP 和 UDP 的区别？为什么选择 TCP？
**回答要点**：
- **TCP**：面向连接、可靠传输、有序、流式协议
- **UDP**：无连接、不可靠、无序、数据报协议

**选择 TCP 的原因**：
- 聊天消息需要可靠传输，不能丢失
- 文件传输需要保证完整性
- TCP 自动处理重传和流量控制

**UDP 的使用场景**：
- 实时语音/视频通话（允许少量丢包）
- 游戏（低延迟优先）

#### Q5: 如何保证线程安全？
**回答要点**：
1. **使用互斥锁（QMutex）**：
```cpp
QMutex m_mutex;
void addToCache(const QString &key, const QByteArray &value) {
    QMutexLocker locker(&m_mutex);
    m_cache[key] = value;
}
```

2. **避免共享数据**：
   - 每个线程使用独立的数据
   - 通过信号槽传递数据（Qt 会自动处理）

3. **使用线程安全的容器**：
   - Qt 的容器在读操作时是线程安全的
   - 写操作需要加锁

#### Q6: 如何处理大量并发连接？
**回答要点**：
1. **当前实现**：
   - 每个连接一个 ClientSocket 对象
   - 使用 QMap 管理在线用户
   - 适合中小规模（< 1000 连接）

2. **优化方案**：
   - 使用线程池处理连接
   - I/O 多路复用（epoll）
   - 异步 I/O（Qt 的事件循环已经是异步的）

3. **扩展方案**：
   - 分布式部署（多台服务器）
   - 负载均衡（Nginx）
   - 消息队列（Redis/RabbitMQ）
