
这是一份为你量身定制的**《C++ Qt 即时通讯系统（IM）开发实战路书》**。
这个文档将项目拆解为了 5个阶段，不仅是为了帮你完成代码，更是为了让你在面试时，每一个功能点都能说出技术深度。
📅 项目总览
项目名称： LinkChat (或者你可以起个更酷的名字，如 SynapseIM)
开发周期： 预计 4-6 周（每天投入2-3小时）
核心技术栈： C++11/17, Qt Network, Qt Sql, Qt Widgets (MVC), CMake/QMake, MySQL/SQLite。
目标代码量： 4500 - 6000 行


🟢 第一阶段：架构设计与协议定义（地基篇）
目标： 搭建工程结构，解决网络编程最核心的“粘包/半包”问题。
耗时： 3-5 天
1.1 工程目录结构 (推荐使用 CMake)
不要把所有代码堆在一起，建立如下结构：
code
Text
LinkChat/
├── bin/              # 编译输出目录
├── common/           # 存放协议头文件、公共工具类 (Client/Server共用)
├── server/           # 服务端源码 (main.cpp, Server.h/cpp, DBManager...)
├── client/           # 客户端源码 (main.cpp, MainWindow, LoginDialog...)
└── resources/        # 图标、QSS样式表、配置文件
1.2 自定义应用层通信协议 (面试必问)
核心难点： TCP 是流式协议，没有边界。你必须定义数据的边界。
任务： 在 common 目录下创建一个 Packet.h。
code
C++
// 简单的协议头设计示例
struct PDUHeader {
    uint32_t totalLength;  // 总包长 (包含Header + Body)
    uint16_t msgType;      // 消息类型 (登录、注册、聊天、文件...)
    uint16_t reserved;     // 保留位 (可用于版本号或校验)
};

// 消息类型枚举
enum MessageType {
    MSG_LOGIN_REQ,
    MSG_LOGIN_RESP,
    MSG_TEXT_CHAT,
    MSG_FILE_REQ,
    // ...
};
作业： 封装一个 NetworkManager 类，实现“发包”和“收包拆包”逻辑。
如何做： 接收端在 readyRead 信号中，先读取头部固定长度，解析出 totalLength，再等待缓冲区数据够了之后，读取剩余 Body。



🔵 第二阶段：核心通信与用户系统（骨架篇）
目标： 实现多用户连接，注册登录，好友列表。
耗时： 7-10 天
2.1 服务端并发模型
技术点： 使用 QTcpServer 监听端口。每当有新连接 (incomingConnection)，实例化一个 ClientSocket 对象。
挑战： 服务端需要维护一个 QMap<int, QTcpSocket*> connectedClients，其中 int 是用户ID。这样A给B发消息，服务器查表就能转发给B。
2.2 数据库设计 (MySQL)
建表是增加代码量的好机会。至少需要三张表：
Users表： uid, username, password_hash (不要存明文!), avatar_id.
Friends表： uid, friend_id, remark.
OfflineMessages表： 对方不在线时，消息存这里，上线后推送。
2.3 客户端 UI 搭建
登录窗口： 输入账号密码。
主界面： 使用 QListWidget 或 QTreeWidget 显示好友列表。
逻辑： 点击登录 -> 发送 MSG_LOGIN_REQ -> 等待服务器 MSG_LOGIN_RESP -> 成功则跳转主界面。


🟡 第三阶段：聊天功能与 Model/View 优化（核心篇）
目标： 实现像微信一样的气泡聊天界面，而不是简陋的文本框。
耗时： 10-14 天
3.1 聊天界面升级 (刷代码量神器)
不要用 QTextBrowser 追加文字！要用 Qt Model/View 架构。
Model: 继承 QAbstractListModel，管理聊天记录数据。
Delegate: 继承 QStyledItemDelegate，这是最难也是最出彩的地方。你需要手动 paint() 绘制气泡背景、头像和文字。
参考： 搜索 "Qt Chat Bubble Delegate"。
好处： 这种写法代码量大，且体现了你对Qt高级绘图的掌握。
3.2 消息转发逻辑
A 发送消息 -> Server 收到 -> 查表找 B 的 Socket -> 转发给 B。
扩展： 如果 B 不在线，存入 MySQL 的 OfflineMessages 表。B 下次登录时，Server 自动推送。


🟠 第四阶段：文件传输与多线程（高级篇）
目标： 能够发送文件，且不卡死界面。
耗时： 7-10 天
4.1 文件传输协议
不要把大文件一次性读入内存！
逻辑：
A 发送“文件请求头”（含文件名、大小）。
Server 转发请求给 B。
B 接受后，建立连接。
A 将文件切片（例如每次4KB），循环发送。
4.2 多线程处理 (关键加分项)
如果你在主线程发1GB的文件，界面绝对卡死。
方案： 客户端创建一个继承自 QThread 的 FileTransferThread。
使用 signals/slots 机制：子线程每发送一部分，emit 一个信号更新主界面的 QProgressBar。


🔴 第五阶段：完善、美化与简历包装（交付篇）
目标： 把“能用”变成“好用”，并打包发布。
耗时： 5-7 天
5.1 细节完善 (Feature Creep)
为了凑够 5000 行，你需要加这些“边角料”：
心跳包 (Heartbeat)： 客户端每5秒发一个空包，服务器15秒没收到断开连接（检测死链接）。
配置文件： 加载 config.ini 读取服务器IP和端口。
日志系统： 封装一个 Logger 类，把 qDebug() 输出重定向到 log.txt 文件中，包含时间戳。
5.2 界面美化 (QSS)
写一个 style.qss，定义按钮的 hover 效果、滚动条样式、窗口圆角。
技巧： 去找一些开源的 QSS 样式库直接魔改。
5.3 简历怎么写 (README)
在你的 GitHub README 中，必须包含：
架构图： 画一张 Visio 或 ProcessOn 的图，展示 Client-Server-Database 的关系。
演示 GIF： 录制一个发文字、发文件、断线重连的动图。
编译指南： 既然用了 CMake，就要告诉别人怎么 Build。
💡 给你的“作弊”小建议 (如何更高效完成)
不要从零手写所有UI： 复杂的布局可以用 Qt Designer 拖拽，然后看生成的 ui_xxx.h 学习代码，再慢慢转为手写代码（如果为了增加代码量）。
善用 GitHub 搜索：
搜 Qt Chat 或 Qt IM。
不要直接抄袭，要**“借鉴模块”**。比如：你不会写气泡聊天，就专门找一个气泡聊天的Demo，把它的 Delegate 代码读懂，移植到你的项目里。
每天 Git Commit： 保持每天都有代码提交记录。面试官看 GitHub 即使不看代码，看到绿油油的提交记录（Contribution Graph）也会觉得你很有毅力。
